### Open Files or Text in Editor (TTY::Editor.open)

Source: https://context7.com/piotrmurach/tty-editor/llms.txt

The primary class method to open files or text content in an editor. It automatically detects available editors and launches one. It returns `true` on success or `false` on failure, unless `raise_on_failure` is set to `true`. Supports opening single/multiple files, editing raw text, forcing specific editors, and passing environment variables.

```ruby
require "tty-editor"

# Open a single file in the default editor
TTY::Editor.open("/path/to/file.txt")
# => true

# Open multiple files at once
TTY::Editor.open("file1.rb", "file2.rb", "config.yml")
# => true

# Edit text content directly (creates a temporary file)
TTY::Editor.open(text: "Enter your commit message here")
# => true

# Create a new file with initial content
TTY::Editor.open("/path/to/new_file.md", text: "# New Document\n\nStart writing...")
# => true

# Force a specific editor (ignores VISUAL/EDITOR environment variables)
TTY::Editor.open("/path/to/file.txt", command: "vim -f")
# => true

# Provide multiple editor choices
TTY::Editor.open("/path/to/file.txt", command: ["vim", "emacs", "nano"])
# => true (opens selection menu if all are available)

# Pass environment variables to the editor process
TTY::Editor.open("/path/to/file.txt", env: {"TERM" => "xterm-256color"})
# => true

# Raise an exception on failure instead of returning false
begin
  TTY::Editor.open("/nonexistent/path", command: "invalid_editor", raise_on_failure: true)
rescue TTY::Editor::CommandInvocationError => e
  puts "Editor failed: #{e.message}"
end
```

### Read Editor from Environment Variables

Source: https://context7.com/piotrmurach/tty-editor/llms.txt

Explains how to use `TTY::Editor.from_env` to read editor commands from the `VISUAL` and `EDITOR` environment variables. It shows how to use these detected editors with a fallback to the system default if none are set.

```ruby
require "tty-editor"

# Check what editors are configured in environment
env_editors = TTY::Editor.from_env
# => ["vim"]  # If EDITOR=vim is set

# Example with environment setup
ENV["VISUAL"] = "code --wait"
ENV["EDITOR"] = "vim"

editors = TTY::Editor.from_env
# => ["code --wait", "vim"]

# Use environment editors with fallback
editors = TTY::Editor.from_env
if editors.empty?
  puts "No VISUAL or EDITOR set, using system default"
  TTY::Editor.open("file.txt")
else
  TTY::Editor.open("file.txt", command: editors.first)
end
```

### Open Editor with Conditional Logic

Source: https://context7.com/piotrmurach/tty-editor/llms.txt

Demonstrates how to open a text editor based on the availability of specific editors like 'code' (VS Code) or 'vim'. If neither is found, it prompts the user to install one.

```ruby
if TTY::Editor.exist?("code")
  TTY::Editor.open("file.txt", command: "code --wait")
elsif TTY::Editor.exist?("vim")
  TTY::Editor.open("file.txt", command: "vim")
else
  puts "Please install VS Code or Vim"
end
```

### Summary

Source: https://context7.com/piotrmurach/tty-editor/llms.txt

TTY::Editor is ideal for CLI applications that need to capture user input through a familiar text editing interface. Common use cases include editing configuration files, composing commit messages or multi-line text input, modifying templates before processing, and any scenario where a simple text prompt would be insufficient. The automatic editor detection ensures the application works across different environments without requiring users to configure their preferred editor manually.

Integration is straightforward - add the gem to your Gemfile, require `tty-editor`, and call `TTY::Editor.open` with your content. For applications that need to open editors multiple times, creating a reusable instance with `TTY::Editor.new` provides better performance by caching the editor lookup. The library integrates well with other TTY toolkit components and follows Ruby conventions for error handling and configuration through both method arguments and block-based DSL syntax.
