### Structured Data Logging with TTY::Logger

Source: https://context7.com/piotrmurach/tty-logger/llms.txt

Explains how to add structured key-value data to log messages for machine-parseable output. This includes defining global structured data during logger creation or passing it per-message. Examples demonstrate different ways to include structured data, including using a JSON formatter.

```ruby
# Global structured data attached to all messages
logger = TTY::Logger.new(fields: { app: "myapp", env: "prod" })

logger.info("Server started")
# => i info    Server started             app=myapp env=prod

# Per-message structured data
logger.success("Request processed", user_id: 123, duration_ms: 45)
# => v success Request processed          user_id=123 duration_ms=45 app=myapp env=prod

logger.error("Payment failed", order_id: "ORD-456", reason: "insufficient_funds")
# => x error   Payment failed             order_id=ORD-456 reason=insufficient_funds app=myapp env=prod

# Structured data via block for lazy evaluation
logger.info { ["Database query completed", { table: "users", rows: 1500, time_ms: 23 }] }
# => i info    Database query completed   table=users rows=1500 time_ms=23 app=myapp env=prod

# JSON formatter for structured data
json_logger = TTY::Logger.new do |config|
  config.formatter = :json
end
json_logger.info("Event logged", event: "page_view", page: "/home")
# => i info    Event logged               {"event":"page_view","page":"/home"}
```

### Log Messages with TTY::Logger Built-in Types

Source: https://context7.com/piotrmurach/tty-logger/llms.txt

Illustrates how to log messages using TTY::Logger's seven built-in types: debug, info, warn, error, fatal, success, and wait. Each type has a unique symbol and color for visual distinction. The examples show logging single messages, multiple message parts, and using blocks for lazy evaluation.

```ruby
logger = TTY::Logger.new

# Basic logging at different levels
logger.debug("Debugging information")
# => * debug   Debugging information

logger.info("Server started on port 3000")
# => i info    Server started on port 3000

logger.warn("Memory usage is high")
# => ! warning Memory usage is high

logger.error("Failed to connect to database")
# => x error   Failed to connect to database

logger.fatal("Application crashed unexpectedly")
# => ! fatal   Application crashed unexpectedly

logger.success("Deployment completed")
# => v success Deployment completed

logger.wait("Waiting for response")
# => ... waiting Waiting for response

# Multiple message parts
logger.info("Deployed", "version", "2.1.0")
# => i info    Deployed version 2.1.0

# Lazy evaluation with blocks
logger.info { "Expensive computation: #{heavy_calculation}" }

# Block returning array of messages
logger.success { ["Processed", "#{items.count}", "items"] }
```

### Create and Use TTY::Logger Instance

Source: https://github.com/piotrmurach/tty-logger/blob/master/README.md

Demonstrates how to instantiate the TTY::Logger and log messages using its built-in types like info, success, warn, error, and fatal. It also shows how to log messages with structured data and metadata.

```ruby
require 'tty-logger'

logger = TTY::Logger.new
logger.info "Deployed successfully"
logger.success "Deployed successfully", app: "myapp", env: "prod"

logger = TTY::Logger.new do |config|
  config.metadata = [:date, :time]
end
logger.info "Deployed successfully", app: "myapp", env: "prod"

logger = TTY::Logger.new do |config|
  config.formatter = :json
end
logger.info "Deployed successfully"

```

### JSON Formatter for Log Aggregation

Source: https://context7.com/piotrmurach/tty-logger/llms.txt

Utilize the JSON formatter with TTY::Logger to generate machine-parseable log output. This is ideal for integrating with log aggregation systems like Elasticsearch or Splunk.

```ruby
logger = TTY::Logger.new do |config|
  config.handlers = [[:stream, formatter: :json]]
  config.metadata = [:all]
end

logger.info("User action", user_id: 123, action: "login")
```

### Output Streams and Formatters

Source: https://context7.com/piotrmurach/tty-logger/llms.txt

TTY::Logger provides robust control over output streams and formatting. You can direct log output to various destinations such as `$stderr`, `$stdout`, files, or even multiple locations concurrently. The gem offers two primary formatters: `:text` for human-readable console output and `:json` for structured, machine-parseable logs, which is ideal for log aggregation systems.
